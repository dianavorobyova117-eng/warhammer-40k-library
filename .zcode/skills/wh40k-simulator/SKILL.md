# 战锤40K 模拟器 Skill v3.13

## 核心原则：尊重规则 + 保留随机性

1. **规则源终审**：任何规则的实现必须以用户黑图书馆App的截图/口供为最终依据。不确定的规则宁可标注"待核"也不要瞎编。
2. **术语即法律（2026-09-02用户严令）**：使用一个名词之前，必须完全知道它的含义——查资料库原文，不许凭印象。例：防守方对冲锋者的自动"反击"不是40K规则（真规则是近战阶段交替结算）；"看守射击"(Overwatch)是1CP战略（对手移动阶段末·24寸内·命中仅自然6·泰坦级不可用），不是免费自动行为。用错一个术语=整个机制实现错误。**双语关键词双源核（2026-09-04 TOWERING勘误事故）**：资料库摘要的翻译标注可能有错（曾把俯射条款写成'巨型(TOWERING)'，巨型实为TITANIC）——关键词规则必须对相关单位档的关键词行原文（如`TITANIC; TOWERING`并存）二次核验，中文近义词绝不当同义词映射。
3. **随机性是灵魂**：骰子运气追踪不是为了消除随机，是为了在战后分析时知道"这局是战术赢了还是骰子赢了"。桌游的戏剧性来自坏骰子和好骰子。
4. **裁判agent是说书人**：不只是掷骰函数——他是解说员+信息中继+气氛组。每轮要用戏剧化的语言描述战场局势，转发给双方指挥官。
5. **引擎改动必须跑测试**：`cd 模拟器/engine && python3 test_ref.py` 必须152条全绿(计数会±3, 看0失败不变量)。
6. **规则检索协议（2026-09-03审阅agent入库; 检索动作固定流程见 模拟器/协作/检索手册.md——词表纪律/宽窗读全段/三处交叉必做）**：动任何规则前先 `grep 关键词 模拟器/data/rules_registry.json`——无命中=新规则，走四件套（①资料库找原文 ②建注册表条目 ③实现加`# RULE:`注释 ④test_ref加断言），**找不到原文只建"待核"条目禁止实现**；命中且状态=待核/bug=不得实现不得展开分析；App终审回写=状态+摘录+代码+测试同commit。数据文件改动后必跑 `python3 engine/data_audit.py` 并对照 reports/数据校验-*.md。
7. **规则钩子架构（2026-09-04 W-002落地, v3.111+）**：阵营规则=RULE_HOOKS表一行{trigger,apply}, 开局_init_hooks()按军表rules触发词子串匹配实例化, 引擎只在18个固定时机遍历——**新增阵营规则=注册表登记触发词+钩子表加一行, 禁止往攻击/移动流水线塞内联if**。序敏感处(hit_reroll pre/post、crit_hits互斥链、charge_roll顺序)改动前先读ref.py头部时机签名注释。
8. **提交纪律（2026-09-04两次带红提交事故后固化）**：commit与验证分离执行——先独立跑全套(test_ref+data_audit)看到绿, 再单独发commit命令; commit用明确文件路径不用git add -A(协作方高频提交, -A会卷走对方未提交工作或被对方卷走自己的)。测试直接改rules[]后必须复调_init_hooks()重建钩子。
9. **执行委托纪律（2026-09-04用户要求: 模拟执行重活不进主上下文）**：
   - **外发清单**（开子agent执行, 主上下文只下发指令+回收摘要）：矩阵批量(crossmatrix)/MC大批次(≥30场统计)/方向性验证跑批/多场景回归跑批/战场数冒烟——一切"重复启动多、过程输出多、结论可一行概括"的机械重活。
   - **豁免清单**（留主上下文）：秒级单命令且输出≤5行的轻验证(如单次test_ref的tail -1、data_audit的关键段grep、build_list单表验分)。
   - **指令文件式下发**：把跑批写成脚本落盘(如/tmp或reports/伴生目录), 子agent prompt只含三要素——`cd <绝对路径> && python3 <脚本> [args]` / 产物落盘路径(reports/xxx.json) / 回收格式。
   - **回收格式约定**（子agent回复≤15行）：①退出码与完成标记 ②关键统计(计数/均值/z值/失败清单, 不贴逐场过程) ③产物json绝对路径。禁止在回复里贴过程日志。
   - **可信关**：子agent产出不可信(verify-first纪律)——结论采信前由主上下文**读产物json抽查关键数字**(读文件=轻, 重跑=重), 不重跑。
   - **长任务挂后台**：run_in_background=true, 主上下文继续其他设计工作, 完成通知后回收。

## 军表铁律（详见 wh40k-lists skill）
- 2000分硬上限，引擎实算>2000=废表；不空分（≥1900，逼近2000）
- 全库分值口径：声明pts=引擎实算；App导出用 wh40k-lists 的阅读法解析
- 用户四张真表（影剑/风暴剑/双超重/毒刃）构成神圣不可动

## 11版阶段规则要点（2026-09-02核对资料库后实装）

- **冲锋**：移动阶段后宣告，目标须12寸内可见；掷2D6≥距离→进入2寸交战圈。突进过/撤退过/被缠/本轮入场常规移动者不可冲；深打落场当轮可冲（20.04 RAW）。失败原地不动。
- **突进(Advance)**：+D6移动，本轮禁冲锋；非突击武器禁射（突击武器-1命中）。
- **看守射击(Overwatch, 核心战略7)**：对手移动阶段末，1CP，24寸内快照，命中仅自然6，泰坦级不可用，每单位每阶段限1次。脚本AI按威胁分值决定开不开（参数`overwatch_min_pts`）。
- **碾碎冲击(核心战略4)**：载具完成冲锋后1CP，掷T枚D6：5+敌吃1致命（上限6），1自吃1致命。
- **近战阶段交替结算**：每单位每轮只战斗一次，主动方先激活，无自动反击。

## 三agent剧场架构（正确版）

```
IG指挥官agent ←─── 裁判agent ───→ 兽人指挥官agent
                        ↓
                 引擎(规则+骰子)
                        ↓
                  战报留档
```

### 裁判agent职责
1. 从引擎获取当前棋盘+单位状态
2. **用戏剧化语言描述战场**（"暗影之剑的火山炮在远处咆哮，维克多中尉紧盯着瞄准镜..."）
3. 将棋盘+局势发给双方指挥官
4. 接收双方JSON军令
5. 喂给引擎执行
6. 获取结果后**叙述发生了什么**（"攻城炮的S16炮弹撕裂了战斗货车的装甲！车内的重甲强兽人被爆炸掀翻！"）
7. 标注骰子运气（"这一轮IG的骰子明显偏冷——命中率比期望低了15%"）
8. 重复直到五轮结束
9. 终局判定+宣布胜者+骰子运气总结

### 指挥官agent职责
1. 收到裁判发来的棋盘+局势描述
2. 根据自己的军表+战术表+当前局势做出决策
3. 回复JSON军令

## 使用方法

```bash
cd 模拟器
python3 engine/ref.py demo --ig 步兵推进-影剑 --orc 表1
```

### 蒙特卡洛统计
```bash
python3 engine/ref.py mc --battles 40
```

### 三agent剧场（正确的斗蛐蛐方式）
1. 主agent初始化对局
2. spawn裁判agent（负责整个对局的说书+掷骰+转发）
3. spawn两个指挥官agent
4. 裁判每轮：
   a. 读棋盘 → 戏剧化描述 → 发给双方
   b. 收双方军令 → 执行引擎 → 叙述结果
   c. 标注骰子运气
5. 终局：裁判宣布胜者+骰子运气判定

### 战报留档
```bash
python3 engine/bard.py --dir battles/目录
```

## 骰子运气分析

每场对局自动追踪命中骰的"需要值vs实际值vs期望概率"：
- z < -1.5 = 骰子背锅（这局输了不怪战术）
- z > +1.5 = 骰子走运（这局赢了别骄傲）
- |z| ≤ 1.5 = 骰子正常（战术定胜负）

100场MC统计：84%的局骰子正常（纯战术决定），16%被骰子显著影响。

## 族参数系统（v3.12+）

`data/params_factions.json` 里每个族有独立AI数值参数：
- charge_aggression: 冲锋欲望（兽人0.9 vs IG 0.3）
- infantry_hold_home: 步兵守家（IG true vs 兽人 false）
- superheavy_to_center: 超重去中场
- cp_bias_defensive: CP防御倾向

## 常见坑

1. 字符串锚点会漂移——patch前先grep确认
2. ×N后缀解析——先精确匹配再模糊
3. 射击致死必须在if real分支
4. 次任务方向——IG对手半场=x<30
5. 战术表targeting要截取括号前名字
6. 改数据后要重跑合并脚本
