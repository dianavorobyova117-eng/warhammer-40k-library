# 先查再做：40K项目工作纪律

> 来源：2026-09-02至09-04用户多轮严令的提炼。每条纪律背后至少有一次真实返工。

## 三道关（改任何东西之前）

### 第一关：术语关
用任何40K名词前（规则名/单位名/武器技能/阶段名），先查 `战锤40K资料库/核心规则/` 六文档和 `data/rules_registry.json`。
- 找到原文 → 摘录贴在代码注释/记忆里再实现
- 找不到 → **标注"待核"，禁止实现**，问用户要App截图
- 血泪案例：伪自动反击（臆造）、受损表方向装反（残血更能抗）、不息炮火三缺口、lethal语义错、 MMM命令双重偏差——全部源于凭印象写

### 第二关：方向关
实现后必须做**方向性验证**：改动应该让谁更强/更弱？实测方向反了吗？
- 案例：受损表装反后"残血载具挨打更少"——用户一眼看穿"残血不会更能抗"，我却当成通过
- 公式：改前测N场 → 改后测N场 → 方向符合游戏逻辑才提交

### 第三关：规模关
- 结论不许基于<30场样本；小样本差异=噪音
- MC配对必须双方引擎分对等（差>5%的结论无效）
- 一次只改一个变量，改完重测基线

## 军表专项
见 wh40k-lists skill。核心：2000硬上限/不空分/用户真表不可动/强化费enh标签/App两套视图读法。

## 静默失败禁令
1. 补丁脚本AssertionError=补丁没打上，**必须重试直到确认生效**（曾因cwd漂移连丢三次补丁）
2. 改文件后**回读验证**（read back），不信任"命令成功"
3. 测试红了不许跳过，找到根因
4. 遇困难当场说，给出选项，不吞不绕
5. 里程碑立即落盘：记忆（project-40k-library.md）+ 报告（reports/）+ git commit，三处同步

## 记忆与skill的自我维护
1. 用户重复指令≥2次 → 必须固化进SKILL.md（不是只写记忆——记忆会膨胀，skill是流程）
2. 每次返工后问自己：这类错误进了检查表吗？
3. 报告文件（reports/）是agent间的交接物，写完要在记忆里留路径
4. 会话收尾自检：本session关键决策是否已在 记忆/reports/SKILL.md 至少一处

## 数据修改纪律
1. units_all.json 改后必跑 `python3 engine/data_audit.py`
2. 库档价只能由App/库实锤修改；表内差异先查口径差再动价
3. 同名不同族单位分族记价；per-model属性×模型数
4. "查无此人"先查映射路由再疑缺档；"两源皆无"不等于销案，必须App终审

## agent协作
- 派agent必带：正确范例（已修好的参照物）+ 数据文件路径 + 验证命令
- agent产出**不可信**，必须独立复检（曾有agent自报"0失配"实则有错）
- 并发写同一文件=互踩，分配互斥的工作范围
- agent完成后的修改必须过全库铁律扫描
